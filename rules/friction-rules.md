# Friction Rules

Use these to convert uncertainty into an action. Friction is not a moral flaw in a game; it is evidence about whether the game competes well for this backlog.

## Field Rules

| Signal | Weight | Keywords | Why |
| --- | ---: | --- | --- |
| long estimated runtime | -2 | 40h, 50h, 60h, 80h, 100h, long, huge, massive | Long games need stronger fit evidence before taking a slot. |
| prior unfinished entry | -5 | prior unfinished, previous unfinished, earlier unfinished | Series debt usually lowers urgency. |
| already sampled without pull | -4 | bounced, stalled, no pull, did not click, bored, tired of, dropped | Prior lack of pull is a strong attention signal. |
| uncertainty worth testing | 2 | curious, maybe, unsure, intriguing, weird, novel, demo, short sample | Some uncertainty should become a short sample rather than a permanent maybe. |
| strong personal pull | 4 | excited, eager, craving, keep thinking, loved similar, exactly my thing | Personal pull beats abstract quality. |

## Decision Biases

- Owned uncertainty should usually become `Sample`, not `Shortlist`.
- A game reaches `Shortlist` only when fit evidence is strong and friction is low.
- A game reaches `Yes: Later` when interest is validated but not urgent.
- A game reaches `No` when it is unlikely to compete for limited attention.
- A wishlist game reaches `Buy Soon` only when it would plausibly enter `Shortlist` or `Yes: Later` after purchase.
- Review sentiment can break ties, but it should not rescue a bad fit.
